## Methodology

For each upstream commit, the audit:

1. Read the upstream commit body (`git show <hash>`) to enumerate the
   exact change.
2. Grepped the fork for the introduced symbols, attribute names, or
   code shapes.
3. If the fork contains an equivalent (byte-different but
   functionally-equivalent) implementation: marked
   `already-present` and skipped writing a full mini-plan.
4. If the fork contains parts but not all: marked `partial` and a
   mini-plan was written narrowly scoping which hunks to import.
5. If the fork does not contain the change: marked `not-present` and
   a full mini-plan was written.
6. If most of the hunks touch files the fork has deleted (M1 / M2):
   marked `mostly-N/A` and queued for re-triage on user demand.

## Anti-pattern guard

If a future Group B verify-pass surfaces a hunk that **was**
already-present at audit time but **is no longer** present (e.g. a
later regression accidentally undid it), do NOT silently re-import
— file a regression report under `.context/sessions/` first and
then write a mini-plan that explicitly cites the regression.
